# Atlas IDE Expert

[![Donate with PayPal](https://img.shields.io/badge/Donate-PayPal-00457C?logo=paypal)](https://www.paypal.com/paypalme/xKnockOut288)

*Deutsche Fassung: [README_DE.md](README_DE.md). The detailed documentation in `docs/` is in German.*

Atlas is an expert for RAD Studio (Delphi/Object Pascal). It replaces the built-in Code Insight with its own windows and adds code analysis with 307 check rules, refactorings, navigation, form support, testing and debugging aids and its own welcome page to the IDE. The data comes from the **Atlas server**, a language server (LSP) of its own that indexes the project and also runs without the IDE as a linter or as an MCP server for Claude Code.

Features and roadmap are tracked in the [issues](https://github.com/xKnockOut/Atlas-IDE-Expert/issues).

## Quick start

You need RAD Studio or Delphi 12 or later. Ready-made downloads are on the [releases](https://github.com/xKnockOut/Atlas-IDE-Expert/releases) page; releases 1.0.0 and 1.1.0 contain the plugin for Delphi 13 only. What is new in 1.1.0 is listed in the [changelog](CHANGELOG.md) (German).

**Option A – add the release package by hand:**

1. Download `atlas-ide-expert-<version>.zip` from the release and unpack it into a permanent folder, e.g. `%LOCALAPPDATA%\Programs\Atlas`. Close Delphi first.
2. Start Delphi, *Component › Install Packages › Add* and select `Win32\Atlas.IDE.Expert370.bpl` from that folder (64-bit IDE: `Win64\…`). The plugin finds the server `AtlasServer.exe` one level above the BPL.
3. Restart Delphi once.

Up to 1.1.0 the package contained the installer `AtlasSetup.exe`; it was removed in 1.2.0. Details (German): [docs/Installation.md](docs/Installation.md).

**Option B – today: build it yourself and install the package in the IDE:**

1. Install Delphi 12 or later and clone this repository.
2. Open `Atlas.groupproj` in Delphi and build all projects for **Win64** (*Build All*). For the classic 32-bit IDE, also build `Atlas.IDE.Expert` for **Win32**.
3. In Delphi, *Component › Install Packages › Add* and select the BPL: `Output\Win32\Debug\Bpl\Atlas.IDE.Expert370.bpl` for the classic IDE (Delphi 12: `…290.bpl`), `Output\Win64\Debug\Bpl\…` for the 64-bit IDE. The plugin finds the server `Output\Win64\Debug\Bin\AtlasServer.exe` there on its own.
4. Restart Delphi once.

More: [Installation](#installation).

## Features

Everything below is implemented in `main`. Features marked *(experimental)* are off by default and can be switched on under *Tools › Options › Third Party › Atlas* once the master switch "Experimentell" is on. The full description of each feature is in [docs/RAD-Studio.md](docs/RAD-Studio.md) and the [CHANGELOG](CHANGELOG.md) (German).

### Writing

- **Code completion** in its own popup: detail panel with coloured declaration and docs, filter chips, fuzzy matching, learning order, favourites (Ctrl+D), typo suggestions ("did you mean"), in-editor preview, `+ Unit` hint for units not yet in `uses`
- **Context-aware:** enum values first, set elements with checkboxes, `case` with all or the missing values, only types after `:`, type arguments matching constraints, attributes after `[` without the `Attribute` suffix (DUnitX and JSON first, constructor in the parameter hint, #465), only exception classes after `raise` and `on E:`, inserted as `EFoo.Create('')` with `CreateFmt` alongside, after `on E:` the classes the `try` block can raise first (XMLDoc `<exception cref>`, `StrToInt` → `EConvertError`) and a warning when an earlier handler already catches the class (#483, `completion.exceptionClasses`), members of `with` objects tagged “aus qryOrders”, with a warning when they hide `Self.Name` or a local (#481, `completion.withOrigin`), anonymous method skeletons where a method reference is expected (`TTask.Run(` gives `procedure begin … end`, `TPredicate<TCustomer>` gives `function(const Value: TCustomer): Boolean`, #468, `completion.anonymousMethods`), full `inherited` call, field and parameter names in `FieldByName('`, the form's components, `Sender` with the matching typecast, same names from different units, helper methods, `uses` list with groups
- **Incomplete code:** if a syntax error before the cursor in the current routine or class declaration limits the context, a warning bar on top of the list says “Results may be incomplete · syntax error in line n”; clicking the line jumps there. Without suggestions the empty state names the error. Errors in other routines and the spot being typed do not count (#457, `completion.syntaxNotice`)
- **Unknown names:** create a local variable, inline variable, field or method right from the list; name suggestions from the type
- **Parameter hint** with all overloads, the active parameter and overload choice by argument types; for `Format` and other format routines it names the placeholder of the argument at the cursor ("placeholder 2 of 2 expects integer"), warns about surplus arguments, invalid placeholders and literals of the wrong type, and colours each placeholder and its argument alike in the editor (#451, `completion.formatPlaceholders`; own routines via `formatFunctions` in `.atlas` or `formatMethods` of `format-args`)
- **Templates:** code templates (`tryf`, `forin`, `prop`, …), your own `*.atlas-snippet` files, the IDE's Live Templates, class-aware templates (`prop`, `create`, `free`) and postfix templates (`List.forin`, `Obj.notnil`, `Obj.free`)
- **Slash commands** run after Enter, such as `/uses Unit`, `/extract`, `/inline`, `/fix`, `/explain`, `/case`, `/helper`, `/test`, `/component`, `/unit`, `/sortuses`, `/cleanuses`
- **Generate menu** (Alt+Ins): constructor, properties, overridden methods, interface methods, surround, templates
- **Guard the free:** after `X := TFoo.Create;` an offer for `try … finally X.Free; end;`
- **Editing helpers**: highlight text matching the selection (#709), highlight exit points of a routine with F3 between them (#698), underline reassigned variables with a hover count and an optional "declare as constant" fix (#712), show the type of the selected expression with conversions, chosen overload and constant value, expanding on repeat (#689, Ctrl+Shift+T), keep method bodies in declaration order: new bodies from class completion move to their place in one undo step, "Order implementation like class" with preview (#660), maintain var blocks: convert a variable to an inline variable at its first assignment and back, tidy the var section (remove unused, sort by first use or name, merge equal types), comments move along (#644), toggle block comment (#703, Shift+Alt+A), new line above or below (#700, Shift+Enter, Ctrl+Alt+Enter), surround the selection while typing (#672), remove the surrounding construct (#657, Ctrl+Shift+Del) with preview, Atlas column in the gutter (#768)
- **Conditional compilation**: outline, hover, go to and checks see only the active `{$IFDEF}` branches of the project, the outline shows the branch condition (#845); `{$IF}` understands `SizeOf`, `High`, `Low`, `RTLVersion111` and `Declared`, `{$IFOPT}` follows the switches of the `.dproj` and local `{$R-}`, unknown values keep both branches active, and the hover on a condition explains its value (#847)
- **Variant records**: fields such as `TRect.Left` or `TMessage.WParam` appear in completion, hover, go to and the outline, tagged with their branch (#846)
- **Class helpers with an ancestor**: `class helper (TBaseHelper) for TFoo` is read as a helper, and `Foo.` also offers the members of the ancestor helper (#848)
- **Less common syntax**: several constraints per type parameter, named OLE arguments (`Open(FileName := 'a.docx')`), calling conventions without a semicolon, `cdecl varargs`, `assembler asm`, local routines in anonymous methods, `{$I file.inc}` as a constant value, long `else if` chains, `@@End` labels in `asm` blocks (#861), control characters such as `^C` and the brackets `(.` `.)` (#862, with an inlay hint showing the code) identifiers with `&&` such as Spring4D's `&&op_Equality` (#1137) , empty record constants `= ()` (#1138), `class threadvar`, `class operator In` and `type AnsiString(1252)` (#1140), `end align 16`, attributes in variant record parts, `IBaz<string>=nil` and `%_0101` (#1142), named arguments with a reserved word such as `Foo(Type := 1)`, calling conventions on anonymous methods and attributes on inline variables (`var [Weak] Obj: IFoo := nil`, #1167) as well as method resolution clauses for functions such as `function IFoo.GetX = MyGetX` (#1134) parse without errors; under `{$SCOPEDENUMS ON}` values need their type prefix, members from `{$I}` inside a class belong to the class (#849)
- **Defines from include files**: a `{$DEFINE}` in a file pulled in with `{$I}` counts for greying out, the outline, checks and the linter; an inlay hint behind `{$I}` lists the symbols the file defines (#860)
- **Documentation comments:** `///` creates the XMLDoc skeleton with placeholders
- **Complete statement** (Ctrl+Shift+Enter), **continue patterns** as ghost text, **continue comments** on Enter
- **Formatting** by its own rules (Ctrl+Shift+Alt+L), since RAD Studio 13 no longer has a formatter; regions between `// atlas-format: off` and `// atlas-format: on` stay untouched, and the same formatter runs without the IDE (`--format-check`, `--format-write`, MCP `format_code`, see [Formatting without the IDE](#formatting-without-the-ide))
- **Move and duplicate lines** (Alt+↑/↓, Shift+Alt+↑/↓), **multiple cursors** *(experimental)*, **linked editing of identifiers** *(experimental)*, **paste with uses completion** *(experimental)*

### Understanding

- **Hover tooltip** in Atlas style instead of Help Insight: declaration, XMLDoc in collapsible sections, clickable types, inheritance chain, values of constants, sets and resource strings, published members of components as a table, symbols in `{$IFDEF}` with their origin, actions (go to, usages, copy declaration, help)
- **Rationale in the hover:** comments such as `// WHY: …`, `// HACK: …` or `// NOTE: …` above a declaration and inside the routine body appear under RATIONALE; `ADR-0007` opens the decision record, `#312` the issue in your tracker (#1123)
- **Values while debugging:** when the process is paused, the tooltip shows the value of the expression under the mouse, evaluated by the IDE's debugger without side effects
- **Type hints** after `var X := …` without a type
- **Code metrics** as a lens after each method header (length, depth, cyclomatic and cognitive complexity, parameters, operands of the largest condition, local variables, exits), after each class (members, inheritance depth without RTL and VCL), the unit name (lines) and the first `uses` (units)
- **Recursion marks** in the gutter, **inactive `{$IFDEF}` branches** dimmed with the reason in the tooltip, **unused uses** dimmed
- **Bracket and block pairs** coloured by depth, with matching block lines
- **Architecture overview** (window *Atlas Architecture*, *View › Atlas › Architecture*): subsystems as groups of closely connected units on a map you can zoom and pan, central units with direct and total dependents and role (foundation, hub), cycles with their round trip and the uses entries that close it, cross links between subsystems (rare or against the main direction) and outliers; double-click opens the unit or the uses entry. Can be saved as an HTML or Markdown report, also with `AtlasServer --architecture` and in the MCP tool `get_architecture`. **Architecture comparison** (#1121): *Save state …* writes a stably sorted JSON state for version control, *Compare with …* (or automatically `architecture.baseline`) shows new and removed cycles, cross links and uses edges between subsystems, units that changed subsystem, grown central units and new or removed units in the *Comparison* tab; on the map new edges are green and removed ones red dashed. Reports get a *Comparison* section, `get_architecture` takes `compareWith`, and `AtlasServer --architecture new.json --compare old.json --fail-on newCycle` breaks a CI run. **Subsystem granularity** (#1366, `architecture.grouping.resolution`, `architecture.grouping.showResolutionSlider`): the *Granularity* slider in the toolbar (coarse … fine, 0.2 to 5.0, double-click = 1.0) sets the resolution γ of the Louvain method; on release the server recomputes in the background, the value is kept in `settings.json`, next to it you see “γ = 1.5 · 12 subsystems”. Reports name a changed γ in the header, saved states remember it, and the comparison points out a different γ; `get_architecture` and `atlas/architecture` take `resolution` for one call. **Splitting** (#1364, `architecture.grouping.maxShare`, `architecture.grouping.minCohesion`): a subsystem holding more than a quarter of all units or with low cohesion is split by a second run on its own units; the parts are named after the section that sets them apart (“Lsp”, “Rules”, “Index” instead of one “Common”), appear as “part of Common” in tables, report and `get_architecture`, sit side by side on the map in shades of one colour and indented under their origin in the legend. **Foundations** (#1365, `architecture.grouping.foundations`: `separate`, `attach`, `group`): units such as logging or JSON helpers used by many subsystems no longer pull them together; they sit in a subsystem of their own, “Fundament”, in the middle of the map (neutral colour, faint edges you can hide, no cross links, no cohesion), or with `attach` join the subsystem with most dependents. **Why a unit is where it is** (#1368, `architecture.explainAssignment`): hovering a unit on the map and its profile below the map show its weighted edges per subsystem (`3 × interface`, `2 × impl.`, `= 8`; edges to the foundation “do not count”), and say when the assignment is close (“with 3 more edges to Data it would lie there”); the *Subsystems* tab marks close units, and the question mark next to it explains how the subsystems are formed with the active settings. The HTML and Markdown reports and `get_architecture` with `unit` show the same table. **Stable colours and names** (#1367, `architecture.grouping.keepPrevious`): after recomputing, subsystems that share more than half of their units with one from the previous state (the saved baseline, otherwise the last computed state in the cache folder) keep its colour and name, so a new unit no longer swaps colours or turns “Index” into “Index 2”; the status line says “Subsystems matched to the state of …”, and *Subsystems ▾ › Rename subsystems* starts over once.
- **Hotspots** (#1354, window *Atlas Hotspots*, *View › Atlas › Hotspots*, `hotspots.enabled`): units and methods that change often and are complex at the same time, score = normalized changes × normalized cognitive complexity from the Git or SVN history of the last `hotspots.months` months (renames followed), with authors, lines, complexity trend against three months ago and last change. Bubble chart (x = changes, y = complexity, size = lines), sortable table on unit or method level, *Change coupling* tab (files changed together in at least 70 % of their commits without a uses edge between them) and *History* tab; double-click jumps to the code, the context menu offers *Show history* and *Show impact* (#1120). Computed in the background and cached until the next commit; without version control a hint instead of data. Also as a report with `AtlasServer --hotspots <file.html|md|json>` (exit code 3 without version control or when switched off) and as the MCP tool `get_hotspots`
- **Call diagram** (#1122, `callHierarchy.diagram`): the call hierarchy as an interactive diagram, switch *Diagram* in the results window, command *Call diagram* in the palette, the Atlas menu and the editor context menu. Start on the left, one column per level, boxes with method name and location; click loads and expands the next level, double-click jumps to the code, drag pans, mouse wheel zooms. Calls through an interface or a virtual method are dashed with the number of implementations, recursion is an arrow back without further expanding, more than 8 children collapse into "+ N …". Outgoing or incoming, filter *Project units only* (RTL/VCL hidden) and *Save as HTML …* (standalone file without external references)
- **Unit relations** (#593, window *Unit relations*, *View › Atlas › Unit relations*): follows the editor and shows what the unit uses (intf/impl, RTL/VCL dimmed in a collapsed group) and who uses it, interface cycles in red with the path in the tooltip, "N units to recompile" after an interface change, direct or all levels, filter; double-click opens the unit, Ctrl+double-click jumps to the uses entry; context menu moves an entry between interface and implementation, removes unused ones or copies the path; Ctrl+double-click in the architecture map opens it for that unit; switched with `architecture.enabled`
- **Cost of an interface change** (#554, `build.showInterfaceCost`): while the caret is in the interface part of a unit, the status bar shows "interface change: 143 units will be recompiled" (tooltip: the first units, click: dependencies); command *Dependencies of this unit* opens *Unit relations* with the users split into "via interface uses" and "via implementation uses" and marks interface entries that are only needed in the implementation ("move to implementation" in the context menu); *Most expensive units for interface changes* opens the architecture overview on *Central units* sorted by "total dependent"
- **Use unit and Find forms** (#786, `unitSearch.replaceUseUnitDialog`, `unitSearch.replaceFormsDialog`): Alt+F11 opens the *Search units* window as "Use unit in <unit>" with an interface / implementation switch (Ctrl+I, default implementation), units already in uses greyed out ("already in uses") and "Cycle via X" as a warning when the compiler would reject the cycle in the interface (only a hint in the implementation); Enter adds all marked units without duplicates as one undo step. Shift+F12 opens the window filtered to forms, frames and data modules; Enter opens the designer. Shift+click and the commands *IDE dialog Use Unit* / *IDE dialog Forms* still open the IDE dialogs
- **Live uses cycles** (#896, `diagnostics.usesCycleLive`, `diagnostics.usesCycleImplementation`): while typing in a uses clause (and on open, using the unsaved state of other open units) an interface cycle is reported as an error "Zirkuläre Unit-Referenz: uC → uA → uB → uC"; each unit in the hover is a link to its uses entry, plus "Show graph" (Unit relations). Quick fix "Move to implementation uses" (sorted like `sortUses`) when the interface needs nothing from the unit, otherwise jumps to the identifiers that need it; a unit naming itself is an error with "Remove entry". Implementation cycles only as a hint with `usesCycleImplementation`; same message in the problem list, MCP and CLI
- **Path between symbols** (*Atlas › Path between symbols …*, command palette, editor context menu *Path from here to …*): how is `TCustomerForm` connected to `TDatabase`? Atlas finds the shortest chain over uses, inheritance, interface implementations, fields, parameters, results, calls and members and draws it in the results window, each step with its kind and location (inferred edges dashed); double-click jumps there, *Show on architecture map* marks the units of the path on the map. Same search as the MCP tool `find_path`; switch: `navigation.symbolPath`

Equal places are grouped ("3 assignments"), deeper levels load when expanded up to `navigation.dataFlow.maxDepth`, cycles, constants and code outside the project end the path, unsafe edges (pointers, `absolute`, `Move`, `FillChar`, `@`) are marked. - **Navigation history** across files
- **Named bookmarks** (Ctrl+Alt+K) and personal **notes** on code lines that never go into the source
- **Quick bookmarks** in a column left of the line numbers: click to set and remove, Ctrl+Shift+1…9 numbers them, Ctrl+1…9 jumps project-wide, Ctrl+Shift+K unnumbered (the IDE's folding chords keep working); they follow code changes and take over the IDE bookmarks as soon as the column is drawn
- **Overview ruler** at the scroll bar with errors, matches and changes; **minimap** *(experimental)*; **sticky scroll** of the enclosing class, routine and large blocks, each kind switchable *(experimental)*
- **TODO overview** of the project from `// TODO`, `// FIXME` and the IDE's to-do format

### Code analysis

The server checks every unit while you type. Findings appear as squiggles, in the tooltip, shortened at the end of the line and project-wide in the dockable window **"Atlas-Prüfung"** (Ctrl+Alt+P); marks move along while typing.

- **Window "Atlas-Prüfung":** live findings of the file, project or project group, filters per kind, category and text, grouping by file, rule or category, sortable columns; Enter jumps, Alt+Enter fixes, context menu to suppress, configure, disable and explain the rule and "Fix all safe findings of …" (bulk fix with a preview per file, deselectable, one undo step per file; `fix.bulk`). "Open first": the unit in the editor is pinned on top, the other open units follow, units that are not open come last, dimmed (or shown normally or hidden); optionally the active unit also shows without findings ("No findings")
- **Finding hover** with severity, rule and action line "Alt+Enter: fix", "Suppress for this line", "Configure rule…"
- **Page "Prüfregeln"** in the options: per rule group a master switch and a table with severity, exclusions and options of every rule, search and catalog text with examples

- **Step filters** (`debug.stepFilters`): F7 no longer stops in one-statement property getters and setters, trivial routines (one assignment to Result or a field), class operators or constructors that only call `inherited`, and skips every routine that matches a pattern such as `*.Log*` or `TBaseForm.*`. The exception bar says "`Order.Customer` is nil" with the field at the read address ("access to field `FAddress` (offset $1C)", confirmed by the debugger or estimated), lists the checked links with ✓/✗ and offers "Where is `Customer` assigned?", "Evaluate expression" and "Copy explanation". ## Building

Open `Atlas.groupproj` in the IDE and **Build All**. The order Text → Common → Windows → server → IDE plugin → tests is set in the project group. Text, Common, Windows and the server must be built for the same platform, otherwise the server does not find the package units. The IDE plugin is set up for Win32 (classic IDE) and Win64 (64-bit IDE from Delphi 12.3); which BPL is loaded depends on the IDE ([ADR 0008](docs/adr/0008-plattformen.md)).

On the command line (RAD Studio command prompt or after `rsvars.bat`):

```bat
msbuild Atlas.groupproj /t:Build /p:Config=Debug /p:Platform=Win32
```

Output goes to `Output\<platform>\<config>\` (`Bin`, `Bpl`, `Dcp`, `Dcu`).

### Building on Linux

Only the server, only for Claude Code sessions in the cloud and other Linux machines without Delphi ([ADR 0013](docs/adr/0013-linux-bau.md)):

```bash
Tools/Linux/Build-AtlasServer.sh --install /usr/local/bin
```

The script first takes the prebuilt program from the `cloud-linux` pre-release (workflow `linux-server.yml`, state of main) if it matches the source. Otherwise it fetches Free Pascal trunk at a pinned commit from the same release or builds it once (about 10 minutes, under `~/.cache/atlas-fpc`), prepares the source with `Tools/Linux/Convert-ForFpc.py` and compiles to `Output/Linux64/Bin/AtlasServer`. If the source has not changed, it does not rebuild. Platform adapters live in `Packages/Atlas.Linux`; `Shell.Platform` picks them. The Linux build does not replace the Delphi build before a merge.

Without any Delphi installation, `AtlasServer --check X.dproj` and the editor take the Delphi version the project expects: `delphiVersion`, otherwise the one matching `<ProjectVersion>` of the .dproj, otherwise the newest known one. It sets only `CompilerVersion`, `RTLVersion` and `VERxxx` (no library paths), so `{$IF CompilerVersion >= 36}…{$ELSE}…{$ENDIF}` keeps only one branch, as in the IDE (#1321).

## CI

- `server.yml`: build of the project group via the IDE plugin `cc.ps1` (RAD Studio Starter has no msbuild, ADR 0007) for Win64 and Win32, including the plugin BPLs `Atlas.IDE.Expert370.bpl` for the classic and the 64-bit IDE (Win32 and Win64, kept as artifacts), and DUnitX tests (Win64 only, ADR 0008). Results as the check "DUnitX-Ergebnisse" in pull requests.
  - The job needs a self-hosted Windows runner (labels `self-hosted`, `windows`, `delphi`) on the developer's workstation. It runs in the signed-in user context, not as a service, because `cc.ps1` starts an IDE, and only while that machine is switched on. Every job starts its own scratch IDE.
  - It runs only with the repository variable `DELPHI_RUNNER=true`; otherwise the job "uebersprungen" says so in the run summary. `CC_SCRIPT` overrides the path to `cc.ps1`.
  - A new push to the same branch cancels the running build (`concurrency`).
- `package-dependencies.yml`: package dependencies, the stdout rule, Delphi 12 compatibility, rule catalog, configuration docs, no Embarcadero sources in `Tests/`, and Atlas windows and editor bars only through their shared hosts.

### Linter mode

`AtlasServer.exe --check <target>` checks without an editor. The target can be a `.dproj` (main file and units), a folder (all `.pas`, `.dpr` and `.dpk` below) or a file. `atlas.json` in the target's folder applies as in the editor. If it is missing, the former `delphi-lsp.json` applies (likewise `delphi-lsp-baseline.json` for the baseline).

The linter loads the same symbol index as the editor (#1112): the target's project and, with `index.projectGroup`, the other projects of the group, from the index cache if it is current. Rules that need types from other units (for example ownership of fields whose type is declared elsewhere, or `case` over an enumeration from another unit) therefore report the same findings as in the IDE. Without a project file the check runs without the index (stderr says so). The MCP server checks with the same index (`get_diagnostics`, `check_code`, `explain_finding`); while it is still loading, `get_diagnostics` says that findings needing the index may be missing.

A check run evaluates each unit once and shares the result with all rules (#1322). Before, rules that ask for the type of many expressions (ownership, casts, typed expressions) extracted the whole unit again for every question, so large units took quadratic time; in the IDE this cost CPU on every change as well. The token at a position is found by binary search instead of a scan from the start of the file (#1323), which large constant arrays made quadratic as well. Measured with the Linux build (before → #1322 → #1323): SynEdit 353 s → 135 s → 113 s, VirtualTreeView 676 s → 93 s → 78 s, HtmlViewer 987 s → 708 s → 116 s, findings unchanged. Searches that a check run repeats all the time no longer start from scratch (#1342): project units and type lookups through the uses units are looked up in name tables and remembered per resolver, yes/no questions to the symbol index stop at the first match, and token searches jump to the start of their range by binary search. A check over the Atlas sources themselves (1,917 units, Linux build) went from 912 s to 594 s, on one core as before and with the same findings.

|---|---|
| `--no-index` | check without the symbol index (faster, but rules that need other units stay silent) |
| `--index-cache <folder>` | folder for the index cache instead of `%LOCALAPPDATA%\Atlas`, e.g. a cache folder kept between CI runs |
| `--format <kind>` | `text` (default, like compiler messages), `json`, `sarif` (SARIF 2.1.0 for GitHub code scanning) |
| `--output <file>` | result into a file instead of stdout |
| `--rules <a,b>` | only these rules, e.g. `syntax` |
| `--units <a,b>` | only these units: name or glob pattern for paths |
| `--min-severity <s>` | `hint`, `info`, `warning`, `error` |
| `--fail-on <s>` | which findings make the exit code 1: `error` (default), `warning` or `never`, so warnings in legacy projects do not break a pre-commit hook |
| `--source-root <folder>` | root of the SARIF paths; defaults to the Git root above the target, otherwise the target's folder. Paths below it carry `uriBaseId` `%SRCROOT%`, files outside appear as absolute `file:` URIs |
| `--profile <name>` | rule profile (`standard`, `fast`, `strict`, `security`, `style` or one of your own from `profiles`); overrides `profile` in `atlas.json` |
| `--baseline <file>` | hide known findings; without it `atlas-baseline.json` next to `atlas.json` applies if present. The editor hides them as well |
| `--update-baseline` | rewrite the baseline from the current findings, exit code 0. stderr first lists entries without a file with their path (renamed, moved or deleted files; they drop out), then the counters: findings, files, added, removed, unchanged |
| `--changed [<base>]` | only files changed according to Git (or SVN, see below) against the merge base with `<base>` (default `main`); changed `.dfm`/`.fmx` check their unit, changed `.inc` all units including them, changed `.dproj`/`.dpk`/`.dpr`/`atlas.json` everything |
| `--diff <ref>` | like `--changed`, but directly against `<ref>` |
| `--include-uncommitted` | with `--changed`/`--diff` also index, working tree and new files |
| `--changed-lines` | only findings in changed lines; together with the baseline only new findings in changed lines |
| `--fix <rules\|all>` | bulk fix (#1352): applies the safe fixes of the rules (confidence from `fix.minConfidence`, default high; only rules marked `safeFix` in the catalog, no fix with a choice), overlapping ones back to front in up to three passes; a file that would then have more syntax errors stays unchanged. Writes all changed files or none, keeping their encoding and line endings. `--units`, `--changed`, `--diff`, `--changed-lines` (only findings in changed lines), `--baseline` (its findings stay) and `--profile` apply. Summary on stderr (fixes per rule, skipped by confidence, unsafe, conflict); exit code 1 if findings reaching `--fail-on` remain |
| `--fix-dry-run` | with `--fix`: write nothing, print the unified diff instead (stdout or `--output`) |
| `--timings [<file>]` | time profile of the run (#1356): index time, the 10 slowest units and rules (sum of ms, calls) and memory per area, as Markdown or, with the extension `.json`, as JSON; without a file on stderr. The findings on stdout or `--output` stay the same (named `--timings` because `--profile` selects the rule profile) |
| `--suppression-stats` | instead of findings: how often each rule is suppressed via `lsp-ignore` (most frequent first, including unused ones), as text or JSON; exit code 0 |
| `--metrics` | instead of findings: code metrics per method (length, nesting depth, cyclomatic and cognitive complexity, parameters, operands, local variables, exits; #66, #980) with the limits from `atlas.json` (`"max"` of the `metric-*` rules); `--format text` writes a Markdown report, `json` the metric data; exit code 0 |
| `--todos` | instead of findings: open TODO entries (#68) from `// TODO`, `// FIXME` and the IDE to-do format `{ TODO 1 -oOwner -cCategory : Text }` with priority, owner and category; more markers via the option `"keywords"` of the rule `todo-comment`; `--format text` writes a Markdown overview, `json` the data; exit code 0 |
| `--architecture <file>` | instead of findings: architecture overview (#1118) of the `--check` target (without `--check` of the current folder) as `.html` (standalone map to zoom, with tables) or `.md`: subsystems, central units, cycles with locations, cross links and outliers; scope, library units and exclusions from `architecture.*` in `atlas.json` or `settings.json`; exit code 0, 3 if the overview is switched off; `.json` saves the state for a comparison (#1121) |
| `--compare <old.json>` | with `--architecture`: compares with a saved state (#1121) and prints the sections as text (or to `--output`); exit code 1 if a kind from `--fail-on newCycle,newCrossLink,subsystemChange,centralGrowth` occurs (default `architecture.failOn`), 3 if the state cannot be read |

Exit code: 1 if a finding reaches `--fail-on` (default: at least one error), otherwise 0; 3 for invocation or read errors. Findings hidden by the baseline never count.

Baseline (#97): an entry in `atlas-baseline.json` records the file, the rule, the enclosing routine (fully qualified like `TFoo.Bar`, outside a routine the section such as `implementation`), a fingerprint of the line without whitespace and a fingerprint of the code ±2 lines around it. The same line in another routine therefore counts as new, as does a finding that moves to another routine. Re-indenting, moved lines and a renamed routine (same context, old name gone from the file) keep their entries. A renamed or moved file loses its entries: its findings show up as new until the baseline is updated. Older files without routines stay readable and are completed on the next update. Suppression comments for findings in the baseline never report `unused-suppression`. In editors the command `atlas.updateBaseline` (`workspace/executeCommand`, argument: URI of the project or folder) updates the baseline and answers with the counters; it checks every file of the project and keeps the server busy meanwhile. In SARIF every result carries `partialFingerprints` (`atlasBaseline/v1` from rule, routine and line, `atlasContext/v1` from the context, each with a running number `:n` for equal values in one file); with a baseline `baselineState` is added: `new`, `unchanged` (as an external suppression) or `absent` (entry without a finding). Text, JSON and the exit code contain only new findings.

In SARIF, `message.text` is the rule's English catalog name without the confidence suffix. The confidence is in `properties.confidence`, the finding's German message in `properties.detail`.

Every rule finding has a confidence (high, medium, low). It caps the severity even if `rules` sets it higher: medium confidence at most warning, low at most hint. Findings below `minConfidence` (default `medium`) are hidden. The confidence is never part of the message text; it is a separate column in the text output (`[Konfidenz mittel]`), `confidence` in JSON, `data.confidence` in LSP and its own line in the plugin's tooltip.

In an SVN working copy, `--changed` without a base compares the working copy with BASE (`svn status`), `--changed <rev>` and `--diff <rev>` with the revision (`svn diff -r`); `--include-uncommitted` adds unversioned files. The nearest working copy above the configuration folder wins (`.git` or `.svn`), Git on a tie; `vcs.provider` in `%APPDATA%\Atlas\settings.json` picks the kind (`auto`, `git`, `svn`) or turns it off (`off`). svn must be installed as a command-line tool (TortoiseSVN with command-line tools is enough). `vcs.git.path` and `vcs.svn.path` pick the program (as on the *Version control* page), `vcs.timeoutSeconds` the time limit per call; if the file under a custom path is missing, `--changed` stops with that cause.

Examples for a pre-commit hook and a GitHub Action that check only changes are in [docs/Beispiele](docs/Beispiele).

#### Formatting without the IDE

The same formatter as *Format document* in the plugin (#1358) runs without the IDE, for example in a pre-commit hook, in CI or for Claude Code. Target and selection as with `--check` (`.dproj`, folder or file, `--units`, `--changed`/`--diff`, `--include-uncommitted`, exclusions from `atlas.json`). The project's formatting rules apply: `format.*` from `atlas.json` over `.editorconfig` over the defaults. The command line does not know the indentation from the IDE's editor options; to get the same everywhere, set `format.indentSize` and `format.useTabs`.

| Parameter | Meaning |
|---|---|
| `--format-check` | formats in memory and compares; per deviating file the first five deviations with line and kind (German text such as `Einrückung 3 statt 2` = is 3, should be 2); `--format json` lists all deviations (lines from 1, kind as an id such as `indent`), `--format diff` prints the unified diff. Exit code 1 on a deviation, a syntax error or unstable formatting, otherwise 0 |
| `--format-write` | writes the formatted files atomically (sibling file, then replace); encoding (UTF-8 with or without BOM, ANSI) and line endings stay, unless `format.endOfLine` asks for others. Exit code 1 only on syntax errors or unstable formatting, 3 if a file could not be written |
| `--changed-lines` | with `--format-check`/`--format-write`: formats only the changed lines like *Format selection* (`textDocument/rangeFormatting`); every other line stays byte for byte |

Files with syntax errors are not formatted and are reported with line and message. Regions between `// atlas-format: off` and `// atlas-format: on` (also as `{ … }` or `(* … *)`, without `on` up to the end of the file) stay untouched including these lines, in the plugin as on the command line. Every run formats the result a second time and reports files that still change.

For Claude Code the MCP tool `format_code` formats a unit by the same rules: with `text` planned code (returns the formatted text, writes nothing), otherwise the file, whole or `startLine`..`endLine`; `dryRun` (default `true`) shows the diff, `dryRun: false` writes like `apply_code_action` (files open in the IDE as one undo step). Switch it off via `mcp.disabledTools`.

Examples: [pre-commit hook](docs/Beispiele/pre-commit-formatierung.ps1) with `--format-check --changed HEAD --changed-lines --include-uncommitted` (with `ATLAS_FORMAT_WRITE=1` it formats itself) and [GitHub Action](docs/Beispiele/github-action-formatierung.yml) with the diff in the log.

## Important: stdout belongs to the protocol

The server speaks LSP over stdin/stdout. Any additional output to stdout (`Writeln`, unhandled exceptions) breaks the communication with the editor. All diagnostic messages go through `ILogger` (`Atlas.Common.Logging`) to `OutputDebugString`, the log file, `window/logMessage` and, for errors, stderr. After starting, the server redirects the stdout handle and `Output` to stderr, so libraries cannot disturb the protocol either.
