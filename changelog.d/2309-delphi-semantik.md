### Neu
- Fünf Prüfregeln für Stellen, an denen Delphi zur Laufzeit anders arbeitet als Free Pascal (#2309): Beide übersetzen den Code, die Tests unter FPC sind grün, erst unter Delphi stimmt das Ergebnis nicht. `managed-result-read-before-set` meldet ein Result vom Typ dynamisches Array oder String, das gelesen wird, bevor die Funktion es setzt (`SetLength(Result, N)` und danach `if Result[I]`, `Result := Result + ...`): Delphi übergibt Result als Variable des Aufrufers, SetLength behält dessen alte Werte (Korrektur `Result := nil` davor). `trygetvalue-out-default` meldet `TryGetValue` als Anweisung, dessen out-Argument vorher einen anderen Wert als die Vorgabe bekam: Delphi setzt ihn auch ohne Schlüssel auf 0, '' bzw. False. `record-array-shared` meldet das Schreiben in ein dynamisches Array eines Records nach `B := A`: Kopie und Original teilen das Array (Korrektur `B.Feld := Copy(B.Feld)` davor). `extractfile-forward-slash` meldet `ExtractFileName`, `ExtractFilePath` usw. auf einem Pfad mit `/`: Unter Windows trennen sie nur an `\` (Korrektur nach `PathDelim`). `hash-overflow-checked` meldet eine überlaufende Multiplikation mit einer FNV-Primzahl ohne `{$Q-}` davor, etwa wenn die Klammer um die falsche Routine steht: Im Debug-Build bricht der Hash mit EIntOverflow ab.
