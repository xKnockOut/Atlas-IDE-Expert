# Atlas IDE Expert in RAD Studio einbinden

Es gibt zwei Wege:

- **Empfohlen: das IDE-Plugin** `Atlas.IDE.Expert` (ADR 0006) für RAD Studio 13 und 12. Es meldet sich als eigener Code Insight-Manager an und bringt eigene Fenster für Vervollständigung, Parameter-Hint und Hover sowie Probleme im Editor, Klammerpaare, Befehlspalette und Compilerprüfung mit (Übersicht in der [README](../README_DE.md)).
- **Eingebauter LSP-Client** (Abschnitt unten). Damit funktionieren Gliederung und Error Insight. Den Hover fremder Server zeigt RAD Studio auf diesem Weg aber nicht an.

## IDE-Plugin

**Mit dem Installer (#495):** `atlas-ide-expert-<Version>.zip` aus dem [Release](https://github.com/xKnockOut/Atlas-IDE-Expert/releases) entpacken und `AtlasSetup.exe` starten. Er zeigt jede gefundene Delphi-Version mit 32- und 64-Bit-IDE, kopiert Plugin und Server nach `%LOCALAPPDATA%\Programs\Atlas` und trägt die BPL unter „Known Packages“ der gewählten IDEs ein. Einzelheiten in [Installation.md](Installation.md#rad-studio-installer). Die Schritte unten sind der Weg ohne Installer, etwa für einen eigenen Bau.

Von Hand:

1. Das Package `Packages\Atlas.IDE.Expert\Atlas.IDE.Expert.dproj` (in der Projektgruppe enthalten) mit der Delphi-Version bauen, in der es laufen soll: für die klassische IDE **Win32**, für die 64-Bit-IDE (ab Delphi 12.3) **Win64**. Ergebnis: `Output\Win32\Debug\Bpl\Atlas.IDE.Expert370.bpl` bzw. `Output\Win64\…`; die Zahl ist die Package-Version (`370` Delphi 13, `290` Delphi 12). Ist das Plugin installiert, sperrt die IDE diese BPL; zum Neubauen das Package vorher entladen.
2. In RAD Studio: *Komponente > Packages installieren > Hinzufügen*, die BPL auswählen.
3. Den Server (`AtlasServer.exe`) mit bauen: Common, Windows und Server für dieselbe Plattform (Win64 empfohlen). Der Server ist ein eigenes Programm und hängt nicht von der Delphi-Version ab.
4. Den Server findet das Plugin in dieser Reihenfolge:
   - *Tools › Optionen › Drittanbieter › Atlas*, Feld „Atlas-Server“ (Registry `HKCU\Software\Atlas\IdePlugin`, Wert `ServerPath`; optional `ServerArguments`, z. B. `--log C:\Temp\atlas.log`). Darunter zeigt die Seite, welcher Server verwendet wird und ob er gefunden wurde.
   - `AtlasServer.exe` neben der BPL
   - `AtlasServer.exe` eine Ebene über der BPL (Aufbau des Installers: `…\Atlas\Win32\Atlas.IDE.Expert370.bpl`, `…\Atlas\AtlasServer.exe`)
   - `..\..\..\Win64\Debug\Bin\AtlasServer.exe`, sonst `..\..\..\Win32\Debug\Bin\AtlasServer.exe`, im Repo also die Build-Ausgabe

Fehlt der Server, meldet das Plugin das im Meldungsfenster und überlässt Vervollständigung und Hinweise der eingebauten Code Insight. Stürzt der Server ab, startet es ihn bei der nächsten Anfrage neu.

Den Umfang des Index stellt *Tools › Optionen › Drittanbieter › Atlas* für alle Projekte ein (#652): alle Projekte der Projektgruppe, alle Units der Projekt-Suchpfade und alle Units der Delphi-Bibliothek. Das Plugin gibt die Werte beim Start und nach jeder Änderung an den Server weiter. Steht `index` in der `atlas.json` eines Projekts, gilt dort die Datei. RTL, VCL und FMX liest der Server einmal je Delphi-Version und Plattform, unabhängig von den Defines des Projekts.

Index und Cache (#492): Der Server legt den Index je Delphi-Version und Projekt unter `%LOCALAPPDATA%\Atlas\Index\<Version>\<Projekt-Hash>\index.atlasidx` ab, die Bibliothek getrennt unter `…\<Version>\Bibliothek\`. Die Datei trägt Formatversion und Prüfsumme; ist sie beschädigt oder veraltet, verwirft der Server sie mit einer Zeile im Protokoll und baut still neu auf. Je Deklaration speichert der Index Signatur, Direktiven (`virtual`, `overload`, `deprecated`, `platform`, …) und den XMLDoc-Kurztext, in Projekt-Units auch die Verwendungen jedes Bezeichners (abschaltbar mit „Verwendungen der Bezeichner mit indizieren“, Registry `IndexUsages`, `index.usages`). Wird die Speichergrenze (Feld „Speichergrenze des Index“, Registry `MemoryBudgetMb`, Standard 768, 0 = ohne Grenze) erreicht, lagert der Server zuerst die Verwendungen aus und lädt sie bei Bedarf aus dem Cache nach, erst danach kürzt er Units. Der Abschnitt „Symbolindex“ der Optionsseite zeigt Units, Deklarationen, Speicher, Größe auf der Platte und die letzte Aktualisierung; die Knöpfe bauen den Index neu auf oder löschen nach Rückfrage alle Caches (`atlas.server.clearIndex`), danach indiziert der Server neu. Während der Server indiziert, ist das Atlas-Feld der Statuszeile gelb („Atlas · Index n %“), und die Vervollständigung vermerkt „eingeschränkt“ in ihrer Fußzeile.

Willkommensseite (#753): Atlas meldet seine Bereiche als Plugins der Willkommensseite an (`ToolsAPI.WelcomePage`, RAD Studio 12 und 13); sie lassen sich mit *Layout bearbeiten* der IDE verschieben und ausblenden. *Atlas › Anzeige › Atlas-Layout anwenden* setzt den Bereich „Atlas“ (Kopf und alle Bereiche in zwei Spalten) oben über die ganze Breite. Dazu schreibt Atlas das Raster der IDE unter `HKCU\Software\Embarcadero\BDS\<Version>\WelcomePage\Layout` und sichert den ganzen Schlüssel vorher nach `%LOCALAPPDATA%\Atlas\welcomepage-layout-backup.json`; *Atlas-Layout zurücksetzen* schreibt ihn exakt zurück. Übernimmt die IDE das Raster erst beim nächsten Start oder überschreibt sie es beim Beenden, wiederholt Atlas den Eingriff beim nächsten Start einmal (Marke `welcomepage-layout-pending`). Ohne Schnittstelle oder mit „Anzeigen in: Fenster ‚Atlas-Start‘“ zeigt *Ansicht › Atlas-Start* dieselben Bereiche in einem andockbaren Fenster. Alles unter *Tools › Optionen › Atlas › Willkommensseite* einstellbar und als Schnellschalter abschaltbar.

Neu in Atlas (#756): Nach einem Update zeigt die Willkommensseite einmalig oben die Karte „Neu in Atlas <Version>“ mit den neuen Funktionen der übersprungenen Versionen, je mit Tastenkürzel, Schalter für die Einstellung und „Ausprobieren“ (Befehl oder Beispieldatei aus `<Installationsordner>\Beispiele`). Quelle ist `whatsnew.json` im Installationsordner; die gesehene Version steht unter `HKCU\Software\Atlas\IdePlugin` in `WhatsNewSeen`. Rechtsklick in die Atlas-Bereiche bietet „Neuigkeiten dieser Version zeigen“ und „Alle Versionen“; `welcomePage.whatsNew` (off, afterUpdate, always) regelt die Karte.

Atlas entdecken (#757): Die Karte zeigt je IDE-Start einen Tipp aus `<Installationsordner>\tips.json` mit Bild aus `Tipps\`, Titel, Text, dem tatsächlichen Kürzel aus der Befehlspalette und „Noch nie benutzt“ bzw. „Zuletzt vor 3 Wochen“; „Ausprobieren“ öffnet `Beispiele\Entdecken.pas` an der Stelle aus `tips.json` oder führt den Befehl aus, „Nächster Tipp“ blättert, „Nicht mehr zeigen“ sperrt den Tipp dauerhaft. Reihenfolge: eingeschaltete, nie benutzte Funktionen zuerst (je Start beginnend nach dem zuletzt gezeigten Tipp), dann die am längsten nicht benutzten; ein Tipp mit `setting` erscheint nur, wenn diese Plugin-Einstellung an ist (bei einer Auswahl wie `WelcomePageWhatsNew`: nicht `off`), einer mit `command` nur, wenn die Befehlspalette den Befehl zeigt; Atlas-Tasten ohne Befehl der Palette (Befehlspalette, Vervollständigung, Parameter-Hint) zeigen ihre Taste aus den Einstellungen bzw. die der IDE. „Ausprobieren“ ohne Beispieldatei führt `try` aus, sonst `command` (beim Tipp zur Befehlspalette öffnet es die Palette; beim Zurücknehmen die Liste „Atlas-Änderungen“ statt sofort zurückzunehmen). `tips.json` hat je Befehl, den man entdecken kann, einen Tipp (28). Bilder: 320 × 180 logische Pixel, bei 100 % Pixel für Pixel, ab 125 % aus der Datei `<name>@2x.png` (640 × 360), bei abweichender Größe einmal mit HALFTONE umgerechnet; ab etwa 560 Pixeln Spaltenbreite steht der Text neben dem Bild, sonst darunter, und in schmalen Spalten wird das Bild mit gleichem Seitenverhältnis kleiner. Ein Bild für helles und dunkles Thema; erzeugt aus `Tools/Tipps/Vorlagen` (siehe [Release.md](Release.md#bilder-der-tipps)). Gezählt wird je Befehl in `%LOCALAPPDATA%\Atlas\usage.json` (nur Kennung, Zähler, Datum; dieselbe Zählung wie die Tastenkürzel-Tipps, #600), gesperrte und zuletzt gezeigter Tipp stehen im Abschnitt `discover` von `%LOCALAPPDATA%\Atlas\shortcut-tips.json`. `welcomePage.discover` schaltet die Karte, `tips.usageTracking` die Zählung ab (dann der Reihe nach); „Zählung zurücksetzen“ und „Gesperrte Tipps wieder zeigen“ stehen auf der Seite *Willkommensseite*.

Meine Issues (#765): Der Bereich „Meine Issues · <Projekt>“ (Kennung `atlas.issues`, Reihenfolge 26, rechte Spalte; im Atlas-Layout ohne festen Platz, weil das Mockup L0 den Bereich ws12 ausblendet) zeigt höchstens 10 mir zugewiesene offene Issues des Projekts, das in „Projekte“ gewählt ist, sonst des aktiven, sonst des obersten. Abgesicherter Start (#722): Wurde die letzte IDE-Sitzung mit Atlas unerwartet beendet (Absturz, Taskmanager), fragt Atlas beim nächsten Start in einem kleinen Fenster unten rechts, ohne den Start aufzuhalten: „Abgesichert starten“, „Normal starten“, „Details“. Abgesichert laufen nur Serververbindung, Statusfeld, Einstellungen, Befehlspalette und Menü; alle Schnellschalter sind für diese Sitzung aus und lassen sich einzeln wieder einschalten (Vorschlag im Fenster). „Normal weiterarbeiten“ meldet alles ohne Neustart an. Nach zwei Abstürzen in 10 Minuten startet Atlas ohne Rückfrage abgesichert. Umschalt beim Laden der Packages (Registry `SafeStartupKey`: shift, ctrl, none), der Schalter `bds.exe -AtlasSafeMode` oder `ATLAS_SAFE_MODE=1` laden nur Einstellungsseite und Statusfeld. Startmarken und Zustand liegen unter `%LOCALAPPDATA%\Atlas\Session`, die gemerkten Einstellungsstände in `%APPDATA%\Atlas\settings-history.json`. Abschalten: auf der Optionsseite *Abgesicherter Start* beide Kästchen aus und Taste „keine“.

Langsamer Start (Bericht N4): Ein Start, der länger als `safeMode.startupTimeoutMs` (Registry `SafeStartupTimeoutMs`, Vorgabe 30000 ms) bis zur freien Nachrichtenschleife braucht, ist kein Absturz und schaltet beim nächsten Start nichts mehr ab. Atlas misst stattdessen seine eigenen Anteile: jedes Teil beim Anmelden, die übrige Anmeldung und Atlas-Aktionen bis zur freien Nachrichtenschleife (etwa Bauen beim Öffnen). Jeder Start schreibt eine Zeile „Start: … ms bis zur freien Nachrichtenschleife, davon Atlas … ms: …“ ins Plugin-Protokoll; ein langsamer zusätzlich eine Zeile im Meldungsfenster (Gruppe Atlas) mit Atlas-Anteil und den längsten Teilen, abschaltbar mit `robustness.hangHint`. Ist der Atlas-Anteil klein, liegt die Ursache bei der IDE, anderen Packages oder dem Projekt.

Formular-Designer (#402): Ein im Designer geöffnetes Formular schickt Atlas etwa eine halbe Sekunde nach jeder Änderung an den Server, auch ungespeichert. Wird ein Ereignis-Handler umbenannt, ändert Atlas die Unit und setzt die Zuordnung im Designer neu; das Formular ist danach geändert und wird mit der Unit gespeichert. Andere Änderungen an einem offenen Formular (etwa eine Komponente umbenennen) lehnt Atlas mit einer Meldung ab und ändert nichts; nicht geöffnete Formulare schreibt Atlas direkt in die Datei.

Bekannte Grenze der Formulardateien (#44): Referenzsuche, Umbenennen und Sprung lesen nur die Formulardateien der Unit, in der die Formularklasse steht (`.dfm`, `.fmx` und FMX-Plattformansichten). Binäre Formulare liest Atlas nie.

Funktionen setzen `Result := Default(<Typ>)`, Prozeduren bleiben leer, ohne `inherited`. Generische Interfaces wie `IComparer<TKunde>` bekommen die eingesetzten Typen (`function Compare(const Left, Right: TKunde): Integer;`). Wird in der Klasse getippt, steht oben in der Liste der Hinweis „3 Methoden von IExporter fehlen“; er ist nie vorgewählt und legt beim Übernehmen alle fehlenden Methoden dieses Interfaces an. Komponenten aus dem Formular (#455): In den Methoden einer Formular-, Frame- oder Datenmodulklasse stehen deren Komponenten als erste Gruppe „Formular frmMain“ in der Liste, rechts mit ihrem Typ. Komponenten in eingebetteten Frames gehören zum Frame und erscheinen nicht.

Sie zeigt die persistenten Felder der Datenmenge, dann die Spalten ihrer SQL-Anweisung (Aliasnamen gelten) bzw. bei `ParamByName` die `:Platzhalter` und die Einträge der Params-Sammlung, rechts mit dem Typ, sofern bekannt. Freigabe absichern (#489): Nach Übernahme eines Konstruktors in `List := TStringList.Create` öffnet das `;` (auch als Commit-Zeichen) oder Enter am Zeilenende ohne `;` eine kleine Liste „Mit try…finally absichern“, rechts die Freigabe (`List.Free`), Fußzeile „Enter anwenden · weitertippen verwirft“. Enter setzt `try`, eine leere Zeile mit dem Cursor, `finally`, `List.Free;` und `end;` darunter, als ein Rückgängig-Schritt; ein fehlendes `;` setzt Atlas dabei selbst und ersetzt die leere Zeile vom Enter. Folgen bis zum Ende der Routine schon Zeilen, gibt es zusätzlich „Bis Routinenende mit try…finally absichern“. Nicht angeboten wird bei Feldern, `Result`, Interface-Variablen, Records, einem Owner (`Create(Self)`, `Create(Application)`), wenn die Variable später zurückgegeben, zugewiesen, an `Add`/`Insert` übergeben oder schon freigegeben wird, und wenn danach schon `try` steht. `completion.offerTryFinally` schaltet das Angebot ab, `completion.freeStyle` = `"freeAndNil"` schreibt `FreeAndNil(List)`.

Code-Vorlagen (#51): Am Anfang einer Anweisung stehen Vorlagen mit dem Badge `sn` und der Marke „Snippet“ in der Liste: `tryf` (try…finally mit Create/Free), `trye`, `forin`, `fori`, `while`, `repeat`, `class`, `record`, `prop`, `propset` (Setter mit Prüfung auf Änderung und `Invalidate`), `comp` (Komponentengerüst) und `reg` (Register-Prozedur). Enter setzt die Vorlage mit der Einrückung der Zeile ein und markiert den ersten Platzhalter; Tippen ersetzt ihn, gleich nummerierte Platzhalter ändern sich mit. Tab springt weiter, Umschalt+Tab zurück, nach dem letzten an die Endposition; Enter springt dorthin und beendet, Esc beendet an Ort und Stelle. Der aktuelle Platzhalter ist umrahmt, verknüpfte gestrichelt, dahinter steht „Platzhalter 1 / 2 · Tab weiter · Esc fertig“. Eigene Vorlagen liegen als `*.atlas-snippet` in `%APPDATA%\Atlas\Snippets` (Atlas liest den Ordner bei Änderung neu; fehlerhafte Dateien überspringt es) und ersetzen mitgelieferte mit gleichem Kürzel:

```
name: Liste anlegen
prefix: lst
description: TStringList mit Freigabe
---
${1:Items} := TStringList.Create;
try
  $0
finally
  ${1}.Free;
end;
```

`${1:Name}` ist ein Platzhalter mit Vorgabe, `${2}` einer ohne, `$0` die Endposition; `$FF` und andere Hexzahlen bleiben Text. Abschalten unter *Tools › Optionen › Drittanbieter › Atlas* („Code-Vorlagen (Snippets) in der Liste anbieten“, Registry-Wert `Snippets`).

`$$` steht für ein `$` im Text. Einsetzen und Ausfüllen sind zusammen ein Undo-Schritt: Strg+Z nach dem Beenden nimmt die ganze Vorlage zurück.

Die Live Templates der IDE (`*.xml` unter `%APPDATA%\Embarcadero\BDS\<Version>\code_templates`) erscheinen ebenfalls in der Liste; Punkte werden zu Platzhaltern, `|end|` zur Endposition, Skripte entfallen. Abschalten mit „Live Templates der IDE als Code-Vorlagen einlesen“ (Registry-Wert `ImportIdeTemplates`). Bei gleichem Kürzel gilt: eigene Vorlage vor IDE-Vorlage vor mitgelieferter.

Eigene Vorlagen lassen sich unter *Tools › Optionen › Drittanbieter › Atlas.Snippets* bearbeiten: Die Liste zeigt alle Vorlagen mit Herkunft; „Neu“ legt eine eigene an, „Als eigene kopieren“ macht aus einer mitgelieferten oder IDE-Vorlage eine eigene, die sie ersetzt, „Löschen“ entfernt eine eigene. Kürzel müssen eindeutig sein; „OK“ speichert die Dateien in `%APPDATA%\Atlas\Snippets`.

Vom Server kommen zusätzlich Vorlagen, die die Klasse kennen. Sie erscheinen nur, wenn in der Zeile außer dem getippten Wort nichts steht:

- `prop` in einer Klassendeklaration, je Feld `FName` ohne Property: setzt `property Name: Typ read FName write SetName;` ein, deklariert `SetName` im private-Abschnitt und legt den Rumpf an.
- `changed` im leeren Rumpf eines Setters: `if FName <> Value then begin FName := Value; Invalidate; end;`.
- `create` im Konstruktor: erzeugt die noch nicht erzeugten Objektfelder (Komponenten mit `Self` als Owner), davor `inherited;`, falls es fehlt.
- `free` im Destruktor: gibt die im Konstruktor erzeugten Felder in umgekehrter Reihenfolge mit `FreeAndNil` frei.

Der Setter sieht überall gleich aus, ob er aus `prop`, `changed`, `propset`, `/prop` oder `/changed` kommt: bei Controls mit `Invalidate`, sonst mit `Changed` bzw. `DoChange`, wenn die Klasse eine davon hat. Mit „Code-Vorlagen (Snippets) in der Liste anbieten“ aus fehlen auch diese Vorlagen.

Postfix-Vorlagen (#188): Hinter einem Ausdruck und Punkt bietet die Liste Vorlagen an, die den Ausdruck umformen; sie tragen die Marke „Postfix“ und stehen hinter allen echten Mitgliedern. Gefiltert wird über das Kürzel, `FKunde.nn` findet also `notnil`. Angeboten wird nur, was zum Typ passt:

| Kürzel | Ergebnis | Typ |
|---|---|---|
| `for`, `forin` | `for var Item in Liste do` | Array, Menge, Typ mit `GetEnumerator` |
| `tryf` | `try … finally Obj.Free; end;` | Klasse |
| `ifa`, `notnil` | `if Assigned(X) then` | Klasse, Interface, Zeiger |
| `nil` | `if not Assigned(X) then` | Klasse, Interface, Zeiger |
| `not` | `not B` | Boolean |
| `if` | `if B then` | Boolean |
| `fmt` | `Format(S, [])` | String |
| `free` | `FreeAndNil(Obj);` | Klasse |
| `try` | `var Foo := TFoo.Create; try … finally Foo.Free; end;` | Konstruktoraufruf |
| `var` | `var Name := X;` | jeder Ausdruck |
| `exit` | `Exit(X);` | in einer Funktion |

Anweisungen (alles außer `not` und `fmt`) gibt es nur, wenn der Ausdruck die Zeile beginnt. Der Ausdruck reicht bis zum Anfang der Anweisung, auch über Aufrufe und Typumwandlungen (`GetKunde(1).notnil`, `TFoo(Obj).free`), nicht über Zeilen hinweg. Nach einem Kopf wie `if … then` steht der Cursor eingerückt in der Folgezeile; Variablennamen (`Item`, `Foo`) sind Platzhalter wie bei den Code-Vorlagen. Ohne Inline-Variablen (Delphi vor 10.3 oder `refactoring.inlineVar` aus) entstehen `for Item in Liste do` und `Foo := …;` mit Eintrag im `var`-Abschnitt der Routine; dann nur, wenn der Typ bekannt ist.

Eigene Postfix-Vorlagen sind `*.atlas-snippet`-Dateien mit zwei weiteren Kopfzeilen; `$expr` steht für den Ausdruck:

```
name: Protokollieren
prefix: log
postfix: true
type: class
---
Log.Debug('%s', [$expr.ClassName]);$0
```

`type:` ist ein Merkmal (`any`, `reference`, `class`, `string`, `boolean`, `enumerable`, `constructor`, `function`) oder ein Typname; dann passt der Typ selbst und jeder Nachfahr. Ohne `type:` passt jeder Ausdruck. Abschalten mit `completion.postfixTemplates` in der `atlas.json` (*Tools › Optionen › Drittanbieter › Atlas*, Seite Vervollständigung); „Code-Vorlagen (Snippets) in der Liste anbieten“ betrifft die Postfix-Vorlagen nicht.

Kontexte der Vervollständigung (#31): Nach `inherited ` stehen nur Methoden und Konstruktoren der Vorfahren zur Wahl. Nach `class(`, `is`, `is not`, `as` und nach `:` in Deklarationen (auch `var X: …` in Anweisungen und `on E: …`) erscheinen nur Typen, nach `:` dazu `string`, `array` und `set`. In `property Wert: Integer read ` bzw. `write ` stehen nur Felder vom Typ der Property und Methoden mit passender Signatur, bei Indexparametern samt diesen; auch geerbte. `override ` am Zeilenanfang im Klassenrumpf bietet die überschreibbaren Methoden der Vorfahren an und macht aus der Zeile die Deklaration mit Rumpf. Sobald ein Zeichen getippt ist, kommen Schlüsselwörter passend zur Stelle dazu: in Anweisungen `begin`, `try`, `while` …, im Klassenrumpf `property`, `private`, `override` …, im Deklarationsteil `procedure`, `var`, `type` … (abschaltbar mit `completion.keywords` in atlas.json). `private`- und `strict private`-Mitglieder fremder Klassen bzw. Units und `protected`-Mitglieder außerhalb von Nachfahren erscheinen nicht. In Kommentaren und Strings, auch mehrzeiligen `'''`-Strings, schlägt Atlas nichts vor.

Absturzsicherheit (#493): Kein Fehler in Atlas erreicht die IDE. Tastaturbindungen, Editor- und Compile-Notifier, Zeichnen, Timer, Menü, Optionsseiten und Hintergrund-Threads laufen über einen gemeinsamen Schutz; Fehler landen ohne Dialog im Protokoll `%LOCALAPPDATA%\Atlas\Logs\atlas.log` (rotierend, 5 × 1 MB; je Zeile Atlas-Version, Feature oder Quelle, Fehlerklasse und eine gekürzte, einzeilige Meldung, darunter die Aufrufkette mit Unit, Routine und Zeile aus der Map-Datei neben der BPL). Drei Fehler innerhalb von fünf Minuten schalten nur das betroffene Feature bzw. die betroffene Datenquelle ab (etwa „Vervollständigung (XMLDoc)“, die übrigen Quellen liefern weiter), mit einer Warnung in der Meldungsansicht und einem Eintrag in der Benachrichtigungszentrale („Wieder einschalten“, „Protokoll öffnen“); jede sichtbare Funktion hat dafür ihre eigene Sicherung, derselbe Fehler zählt innerhalb einer Sekunde nur einmal. *Tools › Optionen › Drittanbieter › Atlas* zeigt unten, was abgeschaltet ist, und schaltet es einzeln oder alle wieder ein; ebenso das Menü Atlas. Datenquellen, die der Hauptthread aufruft (Vervollständigung, Parameter-Hint), haben ein hartes Zeitlimit (Standard 200 ms, Feld „Zeitlimit für Datenquellen“, Registry `ProviderTimeLimitMs`, 50 bis 5000); dauert eine länger, bricht Atlas ab. Das zählt nicht als Fehler: Das Protokoll nennt die langsame Quelle höchstens einmal je Minute, und solange ihr voriger Aufruf noch läuft, wird sie übersprungen. Fehler und Zeitlimit des Servers selbst zählen nicht, dafür gibt es Neustart und Zeitlimit des Servers. Endet der Server von selbst, nennt das Protokoll die Ursache aus dem Exit-Code (etwa „Stapelüberlauf (0xC00000FD)“), die Laufzeit, die letzte und die noch offenen Anfragen; das Statusfeld zeigt die Ursache. Was der Server auf stderr schreibt, steht in `%LOCALAPPDATA%\Atlas\Logs\server-stderr.log` (eine Kopfzeile je Start, ab 1 MB beim nächsten Start nach `server-stderr.1.log` verschoben). Den ersten Absturz startet die nächste Anfrage neu; endet der Server zweimal mit derselben Ursache innerhalb von zehn Minuten, startet Atlas ihn nicht mehr von selbst, sondern bietet in der Benachrichtigungszentrale „Server neu starten“ und „Fehlerbericht erstellen…“ an; der Fehlerbericht enthält dann das Ende von server-stderr.log. Beim Schließen der IDE und beim Entladen des Packages setzt Atlas zuerst ein gemeinsames Abbruchsignal: Laufende Anfragen an den Server, Wächter und Zeitlimit-Arbeiter hören sofort auf zu warten, der Server wird spätestens nach 400 ms beendet, und alle Threads enden innerhalb einer Sekunde; die Dauer steht im Protokoll. Editor-Puffer liest und schreibt Atlas nur im Hauptthread, Hintergrund-Threads arbeiten auf Kopien.

Einzelnen Test debuggen (#585): Neben „Test ausführen“ der Code Lens steht „Debuggen“; *Test am Cursor debuggen* bzw. *Test am Cursor ausführen* in der Befehlspalette und „Test debuggen“/„Test ausführen“ im Kontextmenü des Editors gelten für den Test, in dessen Attribut, Deklaration oder Rumpf der Cursor steht (an `[TestFixture]` für die ganze Fixture, in der Zeile eines `[TestCase]` nur für diesen Fall). Endet das Programm, gelten aktives Projekt und Startparameter wie vorher und das Ergebnis steht wie nach „Tests ausführen“ an den Tests. Gehört die Testunit zu mehreren Testprojekten, fragt Atlas einmal und merkt sich die Wahl. Abschaltbar mit „Test debuggen“ (Seite *Debuggen*, Schnellschalter); ohne „Code Lens „Test ausführen““ gibt es keine Marken.

Prüfung vor dem Kompilieren (#529): Mit `build.gate` = warn oder block (*Tools › Optionen › Atlas › Compiler*) prüft Atlas vor jedem make und build, den der Benutzer startet, die Units des Projekts, die sich seit dem letzten erfolgreichen Compile geändert haben (anderer Stand als beim letzten erfolgreichen Compile der Sitzung, sonst neuer als die Ausgabedatei). Geprüft wird über den laufenden Server mit dem Text der Puffer, auch ungespeichert; es zählen Syntaxfehler und Regeltreffer mit Schweregrad Fehler, keine Warnungen und keine Compilermeldungen des vorigen Builds. Die ganze Prüfung darf `build.gateTimeoutMs` (Vorgabe 300 ms) dauern; danach läuft der Compile ungeprüft, der Hinweis darauf erscheint einmal je Sitzung. Nicht geprüft werden Code Insight, die Hintergrundprüfung (#548), Syntaxprüfung, Clean und Aufträge von Claude Code; ohne laufenden Server prüft Atlas nicht.

Schranke für Hinweise und Warnungen (#530): Nach jedem Build des Benutzers mit lesbaren Meldungen bewertet Atlas das Ergebnis selbst (`Atlas.Core.Build.Verdict`) und schreibt eine Zusammenfassung in die Atlas-Gruppe des Meldungsfensters, etwa „Build Kasse erfolgreich, aber 2 Warnungen, 1 Hinweis“, darunter die erste maßgebliche Meldung (Doppelklick springt hin). Die Gruppe bleibt dabei im Hintergrund, der Reiter „Build“ der IDE bleibt vorn. Mit `build.zeroHints` (*Tools › Optionen › Atlas › Compiler*) gilt ein Build mit Warnungen oder Hinweisen als gescheitert: Die Zusammenfassung lautet „Build Kasse gilt als gescheitert: 1 Hinweis (build.zeroHints)“, Atlas holt die Gruppe nach vorn, die Benachrichtigungszentrale zeigt einen roten Eintrag mit „Zur Meldung“, und Tests nach dem Build (#69) laufen nicht. `build.warningsAsErrors` nennt Codes wie `W1035, H2164`, die so wirken, unabhängig von `build.zeroHints`. `build.summary` schaltet die Zusammenfassung ab; einen Build, den die Schranke scheitern lässt, meldet Atlas trotzdem. Bekannte Altlasten: *Aktuelle Compilermeldungen in die Basislinie* (Befehlspalette, `Atlas.CompilerBaseline`) übernimmt die Warnungen und Hinweise des letzten Builds des aktiven Projekts über den Server in `atlas-baseline.json`, dieselbe Datei wie die Regeltreffer (#97); danach zählen nur neue Meldungen, die Zusammenfassung nennt die übrigen als „(3 weitere in der Basislinie)“. Je Unit ersetzt der Befehl deren bisherige Einträge; Units, die ein Make nicht neu übersetzt hat, behalten ihre (für einen vollständigen Stand vorher *Erzeugen*). Ohne laufenden Server zählen alle Meldungen. Der Befehl ist mit `baseline.update` abschaltbar.

Compilerwarnung gezielt abschalten (#531): Steht der Cursor auf einer Zeile mit einer Warnung oder einem Hinweis aus dem letzten Compilerlauf, bietet das Menü der Code-Aktionen (Strg+.) „W1000 hier abschalten ({$WARN SYMBOL_DEPRECATED OFF})“, „W1000 in TKasse.Buchen abschalten“, „W1000 in der ganzen Unit abschalten“ und „W1000 im ganzen Projekt abschalten (Projektoptionen)“. Atlas fragt nach einer Begründung (leer erlaubt, `refactoring.disableWarningReason`), schreibt sie als `// …` hinter den OFF-Schalter und fügt beide Schalter in einem Rückgängig-Schritt ein. Hinweise bekommen `{$HINTS OFF}`/`{$HINTS ON}`; Warnungen, deren Nummer Atlas keinem Bezeichner zuordnen kann (oder die die Delphi-Version des Projekts noch nicht kennt), `{$WARNINGS OFF}`/`{$WARNINGS ON}`, das alle Warnungen dazwischen abschaltet – Atlas sagt das im Titel und im Meldungsfenster. Ablaufmeldungen wie H2164 (Variable nie verwendet) oder W1035 (Funktion ohne Ergebnis) prüft der Compiler erst am Ende der Routine; für sie ist die Routine die bevorzugte Aktion, um die Zeile gibt es sie nicht. Die Projektvariante fragt nach und trägt `DCC_<Bezeichner> = false` in die Basiskonfiguration ein (wie *Projekt › Optionen › Compiler-Meldungen*); das Projekt gilt danach als geändert. Abschaltbar mit `refactoring.disableWarning`.

Schnellkorrekturen für Compilermeldungen, Teil 2 (#549): Auf einer Zeile mit einer der folgenden Meldungen des letzten Compilerlaufs bietet das Menü der Code-Aktionen (Strg+.) eine Korrektur an, die bevorzugte zuerst. H2443 (Inline-Funktion nicht erweitert): „uses System.Generics.Collections ergänzen (H2443)“, die Unit steht in der Meldung, Atlas trägt sie ins uses des Abschnitts der Zeile ein. E2003 (Unbekannter Bezeichner): „uses System.Classes ergänzen (E2003: TStringList)“ für jede Unit, die den Bezeichner deklariert, RTL- und VCL-Units zuerst; steht der Cursor schon auf dem Bezeichner, bleibt es bei der gewohnten uses-Aktion. H2077 (Wert wird nie verwendet): „Wirkungslose Zuweisung an X entfernen“, wenn die rechte Seite nur aus Literalen, Operatoren und lokalen Namen besteht; bei einem Aufruf mit Klammern „Zuweisung an X entfernen, nur Foo aufrufen“; bei einem Namen ohne Klammern (er könnte eine Funktion sein) keine Korrektur. W1035 (Rückgabewert undefiniert): `Result := Default(<Typ>);` direkt hinter dem begin. W1057/W1058 (implizite String-Umwandlung): `string(…)` bzw. `AnsiString(…)` um die rechte Seite der Zuweisung oder, wenn die Meldung eine Spalte trägt, um das Argument dort. Steht dieselbe Meldung mehrmals in der Datei, fasst „Alle W1057 in der Datei beheben (n)“ alle in einem Rückgängig-Schritt zusammen. Abschaltbar mit `refactoring.compilerFixes`.

## Eingebauter LSP-Client

RAD Studio 13 kann fremde Sprachserver (LSP) über stdio einbinden. So ersetzt der Atlas-Server für Delphi-Dateien den eingebauten Code Insight-Server.

## Voraussetzungen

- RAD Studio 13 (Registry-Version `37.0`)
- `AtlasServer.exe` an einem festen Ort, z. B. `C:\Tools\AtlasServer.exe`. Die Datei ist gesperrt, solange die IDE den Server laufen lässt. Für ein Update die IDE schließen oder die alte Datei umbenennen und die neue daneben legen.

## 1. Server im Code Insight-Manager anlegen

*Tools > Optionen > Editor > Sprache > Code Insight > Code Insight-Manager > Neu*

| Feld | Wert |
|---|---|
| Name | `Atlas` |
| Ausführbare Datei | Pfad zu `AtlasServer.exe` |
| Befehlszeilenparameter | leer, oder zur Fehlersuche `--log C:\Temp\atlas.log --log-level debug` (anonymisiert: Pfade und Namen als `datei#N`/`name#N`; `--log-names` schreibt sie im Klartext) |
| Sprachbezeichner | beliebig (siehe Schritt 2) |
| Timeout | `15000` |
| InitializationOptions | `{}` |

## 2. Sprache auf Delphi umstellen (Registry)

Die Sprachliste im Dialog bietet weder `delphi` noch `pascal` an. Deshalb wird der Eintrag mit einer beliebigen Sprache angelegt und die Sprache danach in der Registry geändert. Die IDE muss dabei geschlossen sein.

```
HKEY_CURRENT_USER\Software\Embarcadero\BDS\37.0\LSP\UserDefined\Atlas
  LanguageId = Delphi
```

Danach steht „Atlas“ im Code Insight-Manager für Delphi zur Auswahl. Die Auswahl landet hier:

```
HKEY_CURRENT_USER\Software\Embarcadero\BDS\37.0\Editor\Source Options\Borland.EditOptions.Pascal
  Insight Manager = Atlas
```

## 3. Prüfen

1. Die IDE neu starten und eine `.pas` aus einem Projekt öffnen.
2. Im Log (mit `--log`) sollten diese Zeilen stehen:
   - `Kein Arbeitsbereichsordner gemeldet; Ordner werden aus den geöffneten Dateien abgeleitet`
   - `Arbeitsbereichsordner: <Ordner mit der .dproj>`
   - `Symbolindex für … fertig in … ms`
3. Über einem Bezeichner hovern. Der Tooltip zeigt die Deklaration.

## Verhalten des RAD-Studio-Clients

- **Kein Arbeitsbereich:** Die IDE meldet `rootUri` als `file:///` und keine `workspaceFolders`. Der Server leitet den Arbeitsbereich deshalb aus jeder geöffneten Datei ab: Er nimmt den nächsten Ordner mit `.dproj` oder `.groupproj` darüber.
- **Nur Klartext:** Die IDE kann kein Markdown (`hover.contentFormat = ["plaintext"]`). Der Server liefert Hover deshalb als Klartext.
- **Neustarts:** Jede gestartete IDE startet einen eigenen Server. Die Voreinstellung „Restart server each time a project is activated“ startet ihn zusätzlich bei jedem Projektwechsel neu. Die IDE beendet den Server hart, ohne `shutdown`/`exit`. Im Log fehlt deshalb die Zeile „Beendet mit Exit-Code“. Das ist kein Absturz. Seit #175 steht beim nächsten Start „N frühere Serverläufe ohne Endzeile (von der IDE beendet oder abgestürzt)“; trennt die IDE nur die Verbindung, steht „Verbindung beendet: Eingabe geschlossen ohne exit (IDE hat die Verbindung getrennt)“ vor „Beendet mit Exit-Code 0“. Einen echten Absturz zeigt „Server abgebrochen“ mit Fehlerklasse; das Diagnoselog unter `%LOCALAPPDATA%\Atlas\Logs\Diagnose` hält dasselbe als `run end reason …` fest.
- **Vervollständigung:** Der Server meldet `completionProvider` und beantwortet `textDocument/completion` (#31). Die IDE meldet `completion.completionItem.documentationFormat = ["plaintext"]`; die Doku in `completionItem/resolve` kommt dann als Klartext (ganzer XMLDoc-Text), an Clients mit Markdown als `MarkupContent`.
- **Sprachkennung:** In `didOpen` sendet die IDE `languageId = "pascal"`. Der Server wertet `languageId` nicht aus, das ist also unschädlich. Die Protokollaufzeichnung `Tests/Data/Protocol/rad-studio-client.json` spielt genau diesen Client nach (`rootUri` `file:///`, Klartext, `pascal`).

## Fehlersuche

- `--trace <Datei>` schreibt den JSON-RPC-Verkehr mit. Die Datei wird bei jedem Start neu angelegt. Ist sie belegt, weil eine andere IDE schon einen Server laufen hat, schreibt der Server nach `<Datei>-<PID>.<Endung>` und nennt den Namen im Log.
- Ein Absturz erscheint im Log mit Stacktrace. Fehlt im Log nur die Zeile „Beendet mit Exit-Code“, hat die IDE den Server beendet.
