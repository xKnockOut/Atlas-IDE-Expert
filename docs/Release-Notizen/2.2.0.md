*English version below.*

Atlas 2.2.0 ist das Release für Debuggen, Testen und Lecks. Der Debugger bekommt eigene Fenster für Aufrufstapel, Variablen, Haltepunkte und Ereignisse, sieht voraus, welche Zweige als Nächstes laufen, und hält an, wenn sich ein Feld ändert. Für DUnitX gibt es das Fenster „Atlas-Tests“ mit Testlisten und Protokoll je Test, und Lecks führen jetzt direkt zur Stelle, an der das Objekt entstand.

Die vollständige Liste steht im [Changelog](https://github.com/xKnockOut/Atlas-IDE-Expert/blob/main/CHANGELOG.md) (Abschnitt 2.2.0). Nach dem Update zeigt die Karte „Neu in Atlas“ auf der Willkommensseite die wichtigsten Neuerungen.

## Debuggen
- Eigene andockbare Fenster: „Atlas-Aufrufstapel“ mit Parameterwerten, Suche und Vergleich zum letzten Halt (#843), „Variablen“ mit Autos und Suche (#853), „Haltepunkte“ mit Suche, Etiketten und Trefferzahlen (#863), „Parallele Aufrufstapel“ aller Threads (#837) und das Ereignisprotokoll mit Filter und Sprung (#580).
- „Warum bin ich hier?“ zeigt die Werte der umgebenden Bedingungen (#1878), „Bedingungen vorausschauen“ die Ergebnisse der kommenden `if`, `while` und `case` und blendet übersprungene Zweige blass (#2169).
- Debug-Hover aufklappen mit geänderten Werten (#895), Werte direkt ändern (#868), Werte anheften (#526).
- Haltepunkte: auf Methoden nach Muster (#855), nur für ein Objekt (#857), Anhalten, wenn sich ein Feld ändert (#584), Regeln mit Trefferbedingung, Thread-Filter und Abhängigkeit (#864), Sätze (#586), Prüfung vor dem Start (#577), sie wandern mit dem Code (#841), Logpunkte (#583), bis hier ausführen per Klick im Rand (#851).
- Threads im Quelltext (#852), „Was wartet worauf?“ für Verklemmungen (#587), Modul der Fehleradresse bei Zugriffsverletzungen (#1820), Fenster „Kein Quelltext“ (#869).
- Neu starten mit einem Griff (#872), erneut an Prozess anhängen (#2171), mehrere Programme gemeinsam debuggen (#867), laufendes Programm vor dem Build beenden (#551).
- Experimentell: Stichproben-Profiler („Mit Profil ausführen“, MCP-Werkzeug `get_profile`, #2057), Herkunft eingereihter Methoden im Aufrufstapel (#859).

## Testen
- Fenster „Atlas-Tests“ mit allen Tests, Stand, Filtern und Mehrfachauswahl (#1776), öffnet sich bei Fehlschlägen von selbst (#2467), Testlisten als Reiter (#2167), Protokoll je Test (#2168), Teststand in der Statusleiste (#1777).
- Fehlschlag an der Assert-Zeile mit „erwartet/erhalten“ (#1771) und Vergleich nebeneinander (#1779), veraltete Ergebnisse (#1770), Dauer und langsame Tests (#1772), wackelnde Tests (#1773), Tests mehrfach oder in zufälliger Reihenfolge (#1782), betroffene Tests beim Speichern (#1775).
- Marke „getestet von“ (#1778), ungetestete Methoden (#1783), Testabdeckung aus DelphiCodeCoverage im Rand (#275), experimenteller Mutationslauf (#1460).
- Tests anlegen: aus der Unit (#1226), aus einem Debug-Halt (#1873), Grenzfälle aus den Bedingungen einer Routine (#2173), `[TestCase]`-Fälle als Tabelle (#1879), Vergleichsdateien (#1881), Schnellbefehle `/mock`, `/testcase`, `/dump`, `/assert` (#305).
- Neue Prüfregeln für DUnitX: unpassende `[TestCase]`-Werte, nie registrierte Testklassen, aussagelose Asserts, im TearDown nicht freigegebene Felder, falsch verwendete Attribute (#1882, #1780, #1781, #154, #2197).

## Lecks
- Fenster „Atlas-Lecks“: Leckbericht am Programmende mit Vergleich zum letzten Lauf und den verdächtigen `Create`-Stellen (#1875).
- Lecks je Test an der Testmarke (#1774), Leckprüfung für ein Projekt einrichten (FastMM4/FastMM5, #1880), Marke „Wer gibt das frei?“ an jedem `Create` (#1877).
- Leck- und Absturzberichte von FastMM, madExcept, EurekaLog und JclDebug im Editor, Adressen über die Map-Datei (#74); sechs neue Leck-Prüfregeln (#1876).
- Speicherverlauf beim Debuggen, experimentell mit Objektzählung je Klasse (#858).

## Außerdem
- Vervollständigung: Mitglieder nach `if X is T then` (#2107), Hinweis auf wegen der Sichtbarkeit ausgeblendete Mitglieder samt „Sichtbarkeit anheben“ (#2108), Rangfolge aus der Verwendung im Projekt (#2109).
- GitHub im Issue-Tracker: Status im GitHub-Projekt, verknüpfter Branch, Schließgrund, Pull Request beim Beenden und Issue-Formulare (#2134–#2138).
- Eigenes Desktop-Layout im Formular-Designer (#2079); Hauptmenü *Atlas* in Untermenüs gegliedert; alle andockbaren Atlas-Fenster unter *Ansicht › Atlas*. Atlas-Fenster behalten ihren Platz im Desktop-Layout (feste Namen).
- uses-Einträge im interface, die nur die implementation braucht, erscheinen in Hinweisfarbe (#2465).
- Qualität: Die Testsuite läuft unter Delphi ohne ein einziges Leck; der Speicherrest beim Beenden ist ein Kriterium jedes Testlaufs.

Atlas 2.2.0 is the release for debugging, testing and leaks. The debugger gets its own windows for call stack, variables, breakpoints and events, predicts which branches run next and stops when a field changes. For DUnitX there is the "Atlas Tests" window with test lists and a log per test, and leaks now lead straight to the place where the object was created.

The full list is in the [changelog](https://github.com/xKnockOut/Atlas-IDE-Expert/blob/main/CHANGELOG.md) (section 2.2.0, German). After the update, the "What's new in Atlas" card on the welcome page shows the main changes.

## Debugging
- Dockable windows of its own: "Atlas call stack" with parameter values, search and comparison with the last stop (#843), "Variables" with autos and search (#853), "Breakpoints" with search, tags and hit counts (#863), "Parallel stacks" of all threads (#837) and the event log with filter and jump (#580).
- "Why am I here?" shows the values of the surrounding conditions (#1878), "Predict conditions" the results of the upcoming `if`, `while` and `case` and dims skipped branches (#2169).
- Expandable debug hover with changed values (#895), change values directly (#868), pin values (#526).
- Breakpoints: on methods by pattern (#855), only for one object (#857), break when a field changes (#584), rules with hit condition, thread filter and dependency (#864), sets (#586), check before starting (#577), they move with the code (#841), logpoints (#583), run to here by clicking the margin (#851).
- Threads in the source (#852), "What is waiting for what?" for deadlocks (#587), module of the fault address on access violations (#1820), "No source" window (#869).
- Restart with one key (#872), reattach to a process (#2171), debug several programs together (#867), stop the running program before the build (#551).
- Experimental: sampling profiler ("Run with profile", MCP tool `get_profile`, #2057), origin of queued methods in the call stack (#859).

## Testing
- "Atlas Tests" window with all tests, state, filters and multiple selection (#1776), opens by itself on failures (#2467), test lists as tabs (#2167), log per test (#2168), test status in the status bar (#1777).
- Failures at the assert line with "expected/got" (#1771) and side-by-side comparison (#1779), outdated results (#1770), duration and slow tests (#1772), flaky tests (#1773), run tests repeatedly or in random order (#1782), affected tests on save (#1775).
- "Tested by" marks (#1778), untested methods (#1783), test coverage from DelphiCodeCoverage in the gutter (#275), experimental mutation run (#1460).
- Create tests: from the unit (#1226), from a debug stop (#1873), boundary cases from the conditions of a routine (#2173), `[TestCase]` cases as a table (#1879), approval files (#1881), slash commands `/mock`, `/testcase`, `/dump`, `/assert` (#305).
- New check rules for DUnitX: `[TestCase]` values that do not fit, test classes that are never registered, asserts that hide the values, fields not freed in TearDown, misused attributes (#1882, #1780, #1781, #154, #2197).

## Leaks
- "Atlas leaks" window: leak report at program end compared with the last run, with the suspicious `Create` sites (#1875).
- Leaks per test at the test mark (#1774), set up leak checking for a project (FastMM4/FastMM5, #1880), "Who frees this?" mark at every `Create` (#1877).
- Leak and crash reports from FastMM, madExcept, EurekaLog and JclDebug in the editor, addresses resolved through the map file (#74); six new leak check rules (#1876).
- Memory timeline while debugging, experimental with object counts per class (#858).

## Also
- Completion: members after `if X is T then` (#2107), note on members hidden by visibility with "Raise visibility" (#2108), ranking from usage in the project (#2109).
- GitHub in the issue tracker: status in the GitHub project, linked branch, close reason, pull request on finish and issue forms (#2134–#2138).
- Own desktop layout in the form designer (#2079); the *Atlas* main menu is organized in submenus; all dockable Atlas windows under *View › Atlas*. Atlas windows keep their place in the desktop layout (fixed names).
- uses entries in the interface that only the implementation needs are shown in hint colour (#2465).
- Quality: the test suite runs under Delphi without a single leak; the memory left at shutdown is a criterion of every test run.
