# Forms

Back to the [README](../../../README.md)

- Open forms are sent to the server as the designer has them: references, renames and checks also see unsaved components
- Renaming an event handler also updates its assignment in the designer
- The form's components in completion, `Sender` with the matching typecast
- Checks between form and code and **property rules** for form files with quick fix
- Convert binary forms to text forms

## In the designer

Commands of the [designer bar](Navigating.md#designer-bar) for the selection in the form designer:

- **Tab order** (#603): badges at the top right of every control with a TabOrder; jumps against the reading order, gaps and duplicates in red with a hint, controls without TabStop grey “–”, nested ones as a path “2.1” (`designer.tabOrderPaths`). On the arrow: “Click the order” (clicks assign 0, 1, 2 … per container; Enter keeps it, Esc restores the old order), “Sort by reading order” and “Undo tab order” (also Ctrl+Z while the badges are shown). Shown by itself when a form opens with `designer.tabOrderOverlay`.
- **Select similar** (#738): all components of the same class, also with descendants (from the common base class for a multiple selection), with the same parent, the children or all descendants of a container, with the same stored property value (`Font.Name = 'Tahoma'`) or the same event handler; plus “Invert selection”. Every entry shows its hit count, Shift while clicking adds to the selection. Scope is the whole form or the parent only (`designer.selectSimilar.scope`).
- **Selection sets** (#739): In the same menu, “Save selection …” (or Ctrl+Shift+S in the designer) stores the selection under a name per form. Ctrl+Shift+1…9 restores the first nine sets; in the menu a click restores, Shift+click adds, Ctrl+click removes, plus overwrite, extend, rename, move and delete. Renamed components stay in the set, deleted ones drop out. Stored locally or shared next to the form (`designer.selectionSets.storage`); the .dfm stays unchanged.
- **Spatial navigation** (#745): Alt+Arrow selects the next control in that direction, Alt+Shift+Arrow adds it, Alt+Home selects the parent, Alt+End the top-left child, Alt+Page Up/Down switches the container. At the edge of a panel it continues into the panel next to it (`designer.spatialNavigation.crossContainers`); a short frame shows the target.
- **Arrange › Width from text** (#730): sets the selected buttons, check boxes and labels to the width of the longest text plus padding, at least 75 px. In a row the gaps stay, and so does the right edge if the row is anchored right; AutoSize and Align without free width stay.
- **Arrange › Arrange button bar** (#732): OK, Cancel, Apply and Help in the right order, equally wide, anchored bottom right; plus Default, Cancel and ModalResult unless the handler closes the form itself. Role from caption, name or ModalResult, own terms in `designer.buttonBar.roles`.
- **Arrange › Duplicate in row …** (#736): select a label/field pair, enter the list “Fax, Mobile, Home”, press Enter: three pairs `lblFax`/`edtFax` etc. with captions “Fax:” … below at the same gap, tab order after the original, `FocusControl` pointing to the new field. Without a list the number counts up (`edtTelefon2`). Outlines of the copies appear in the designer while you type, red on overflow; “Move following controls” makes room. “Undo duplicate” removes the last run.
- **Arrange › Insert space … / Remove space …** (#740): select row 3 of a form, insert 30 px: row 3 and everything below moves down 30 px, a memo with `[akTop, akBottom]` crossing the line gets longer, the form grows if the content no longer fits. Removing stops at the next control above. Columns work the same at the left edge. “Undo space” reverts the last step.
- **Arrange › Fit to content** (#742): a group box with two radio buttons shrinks until both fit with an 8 px margin and the caption; without a selection the form fits itself, buttons with `[akRight, akBottom]` end up 8 px from the edge. Submenu: width and height, width only, height only, all to the same width. “Undo fit to content” reverts the last step.
- **Arrange › Near-aligned edges** (#746): three edits stacked with Left 90, 92 and 90: “Show” reports `edtFax.left -2` and outlines edtFax in the designer for a few seconds; with an offset of 4 px and tolerance 3 nothing is reported. “Align all” moves edtFax to 90 (revert with “Undo align edges”). What is intended is marked with “Mark selection as intended”; the exception is stored in `.atlas-nearalign.json` next to the form and can be checked in. Text baselines of a label and an edit side by side are compared too (approximated from the font).
- **Arrange › Default size** (#747): with `TButton=88,25` in `designer.defaultSizes.table` a newly dropped button is 88 × 25; an entry `TCustomEdit=,23` applies to TEdit and TMaskEdit and keeps the width. “Set default size” without a selection sets every button of the form, a button row at the bottom right keeps its right edge. “Take table from form” enters the most frequent size per class, “Show deviations” (with `designer.defaultSizes.markDeviations`) outlines a 72 × 22 button with “Target 88 × 25”.
- **Arrange › Layer** (#749): three overlapping panels with the topmost selected: “Send backward” (or Ctrl+PgDn) puts it between the other two, in the DFM too. A label on an image: the stack in the submenu lists “lblTitel, imgLogo”, clicking imgLogo selects the covered image. A TLabel cannot be moved above a TEdit; Atlas reports that instead of a change the VCL would not paint.
- **Arrange › Transfer properties** (#726): select btnOk, press Ctrl+Shift+C, tick font and size in the dialog; then select two other buttons and press Ctrl+Shift+V: font and size are transferred, position and caption stay. Transferring to a TLabel lists what the label lacks in the messages view (“lblName: BevelKind skipped”). The ticks for TButton apply again next time, also after a restart.
- **Arrange › Suggest anchors …** (#727): in a search dialog with an edit at the top, a grid below and OK/Cancel at the bottom right Atlas suggests L T R for the edit, all four for the grid and R B for both buttons. A panel with `Align = alBottom` is listed as “handled by Align” without a tick. Unticked rows stay unchanged; “Undo anchors” reverts the change.
- **Arrange › Form texts …** (#728): in a form with “&Save” and “&Search” in the same panel, a label “E-Mail” and a hint “Enter email” the table shows both buttons with “Duplicate access key” and both texts with “Spellings: E-Mail / email”. “Only with notes” hides the rest; after changing “&Search” to “S&earch” the button notes disappear, “Undo text” restores the old text.
- **Label and field** (#729): a label dragged to the left of a TEdit snaps to its text baseline and gets FocusControl = the edit. Moving the edit moves the label along. “Arrange › Label and field › Create labels” on `edtZip` and `cbxPaymentMethod` creates `lblZip` “Zip:” and `lblPaymentMethod` “Payment Method:” to their left.
- **Arrange › Arrange as form grid …** (#731): select five scattered pairs name, street, zip/city and phone: the preview shows one label column, equal row gaps and zip and city in one row. After OK the tab order runs row by row; “Undo grid” restores position and tab order.
- **Arrange › Wrap in / Dissolve container** (#733): select three check boxes, choose “Wrap in › TGroupBox”, enter the name “gbxShipping” and the caption “Shipping”: the group box encloses the check boxes with padding, nothing moves, the tab order stays. “Dissolve container” on a panel moves its children one level up; if the code contains `pnlAddress.Visible := False;`, Atlas shows that line first.
- **Arrange › Fonts and colors …** (#741): an old form shows “Segoe UI 9” (form) and “Tahoma 8 (14)”. “Replace …” with target Segoe UI 9: all 14 inherit the form font again. With only “Name” checked, Tahoma 8 becomes Segoe UI 8. A click on “clRed (2)” selects the two red components.
- **Arrange › Group** (#744): select the label “Address:”, an edit and a button, press Ctrl+G and accept the suggestion “Address”. A click on the button then selects all three, a dashed frame shows “Address”, and Ctrl+arrow moves them together. Alt+click selects only the button. Copying and pasting the three gives the group “Address 2”.
- **Edit captions in place** (#748): select a label, press F2, type “&Name:”, press Tab: the field moves to the edit next to it (Text, Ctrl+H for TextHint), Tab again to the next label. A button “&New” next to “&Next” gets a short red frame. A slow second click on a selected button opens the field as well; a quick double click still creates OnClick.

## Own buttons in the designer bar

Larger features have their own button in the designer bar and their own setting:

- **Measure distances** (#605): while dragging and resizing, guide lines to the nearest neighbour in the same parent or to the inner edge of the parent (padding included) show the distance in DFM pixels, also at 150 % scaling. An edit between two labels shows “8 px” upwards; if two other fields in the same panel are 8 px apart as well, the line turns accent coloured with “8 px as above”. Resizing adds width × height, with “width as btnOk” when a neighbour has the same width. With Alt held, hovering another control shows the distances between the selection and that control without changing anything. The button turns the display off for the session; `designer.measureDistances` and `designer.measureAltKey` switch it off completely.
- **Try size** (#606): the button opens a window showing the form as an image at a preview size: grip at the bottom right, width and height, “Minimum” (from `Constraints.MinWidth/MinHeight`, disabled otherwise), “Design” and the quick sizes from `designer.resizePreviewSizes`. Atlas computes Align, Anchors, AlignWithMargins, Margins, Padding and Constraints following the VCL rules. At 600 × 400 a button with `[akLeft, akTop]` at the right edge is red with “sticks out 175 px on the right, only akLeft, akTop anchored”; a memo with `alClient` grows, a panel with `alBottom` stays at the bottom. Overlaps, width or height ≤ 0, two `alClient` in one parent and anchors on all sides with Align are red as well. Anchors are shown as pins, Align areas tinted (`designer.resizePreviewShowAnchors`). The DFM stays unchanged; Esc closes.
- **Scaling and texts** (#607): The button opens a window showing the form at the chosen scaling (`designer.scalePreviewLevels`, default 100 to 200 %), on a chosen screen (`designer.scalePreviewScreens` or “No limit”) and with original or long texts (all captions and items lengthened by `designer.longTextFactor` percent, “Speichern” becomes “SpeichernSpe” at 30 %). Atlas scales by the VCL rules (`Scaled`, `PixelsPerInch` of the DFM, font height) and measures texts in the component’s real font. At 150 % a label with `AutoSize = False` whose text no longer fits is red with “text 6 px wider than the component”; a form with `ClientHeight = 800` is too tall for 1366 × 768 including frame and taskbar, and the usable area is shown dashed. AutoSize labels grow with their text and are reported when they stick out or overlap. The list of findings is at the bottom; a click selects the component in the designer. The DFM stays unchanged; Esc closes.
- **Gap handles** (#734, own button): four fields in a row with gaps of 7, 15 and 10 px show three pills with these values. Double-click a pill, type “12”, Enter: all gaps are 12 px and the centre of the group stays (with Shift the first, with Ctrl the last component). Dragging changes all gaps at once and snaps at 4, 8, 12, 16 px (Alt: no snapping), arrow keys while holding a pill change by 1 px. For a column the handles work vertically. Whatever then sticks out of the parent gets a red frame and is only applied after confirmation; “Undo gaps” in the arrow menu takes back the last step.
- **Shared resize handles** (#737, own button): select three stacked 180 px edits and drag the right handle of one by 80 px: all become 260 px wide and a label shows “180 → 260 px (3×)”. In `align` mode (`designer.multiResize.mode`) all get the same right edge. Bottom edge and corner work the same; left and top edges with Alt on press or with own handles (`designer.multiResize.leftTopHandles`). Snaps to the designer grid (Alt: no grid). With Shift a button directly to the right moves along. Labels with AutoSize and aligned controls stay and get a dashed frame. “Undo sizes” in the arrow menu takes back the last drag.
- **Quick bar** (#735, own button): select two labels, an edit and a combo box; after a short delay a bar above the selection offers font size −/+, bold, italic, font colour, Enabled, Visible, ParentFont, ParentColor, Anchors L/T/R/B, same width and height (as the first selected component) and Alignment. If only one label is bold, “B” is half filled; one click makes all bold. Alignment only affects the labels and the edit, the combo box has none; the tooltip says “for 3 of 4”. The bar disappears while dragging and comes back afterwards. With `designer.selectionBar.mode = shortcut` it only appears on Ctrl+Shift+Space. “Undo last quick bar change” in the button menu undoes clicks step by step. Buttons and order: `designer.selectionBar.items`.
- **Magnifier** (#743, own button, Ctrl+Alt+L): a small window shows the area under the mouse enlarged, 4× by default with pixel grid and crosshair. Over an edit at Left = 100, Top = 40 in the DFM, the header shows “X 100, Y 40” at its top left corner even at 150 % display scaling, plus the position in the parent. The footer shows “#FFFFFF   clWindow (system colour) …   clWhite” and the edit’s name. Ctrl+Alt+L freezes the view, the arrow keys then move it by one pixel, and Ctrl+Alt+L again makes it follow the mouse. The mouse wheel over the magnifier switches between 2×, 4× and 8×. A left click copies the colour value, the context menu the coordinates. With `designer.magnifier.edges` the edges of the selection and its neighbours appear as lines, so one-pixel offsets stand out.
- **Meaningful names** (#608, own button): the button lists all components with default names such as `Button1` or `Edit3` and proposes names from prefix and text: `Button1` with caption “&Save” becomes `btnSave`, `Edit3` right of the label “ZIP:” becomes `edtZip`, `DBEdit1` with `DataField = CUSTOMER_NAME` becomes `edtCustomerName`, a button with the handler `DoExport` becomes `btnExport`. Order of sources: `designer.nameSuggestSources`; umlauts are replaced (Größe → Groesse) or removed (`designer.nameSuggestUmlauts`). Prefixes come from a built-in table, also via ancestors (`TMyEdit` → `edt`); own ones go in `designer.nameSuggestPrefixes` (`TButton=cmd; TEdit=txt`). Names already taken get a number (`btnSave2`). In the dialog you can tick rows and change proposals; rows without a proposal stay empty and unticked. “Apply” renames the components in the designer, handlers such as `Button1Click` → `btnSaveClick` (`designer.nameSuggestRenameHandlers`) and the other places in the form's unit (outside strings and comments). “Undo last renaming” reverts the last run. Other units are not changed.
- **Search properties** (#524, own button, also in the Atlas menu): the condition `Font.Name = 'Tahoma'` with scope “Project” lists every component with this font per form in the results window; further conditions `Visible = False`, `Tag <> 0`, `Class = TDBGrid`, `Caption contains 'Customer'`, `Hint is set`, `Hint not set`, joined with “and”. Scope current form, project or project group; open forms with their unsaved state, binary forms are skipped. A value set only in the ancestor form counts and is marked “inherited”. Double-click a hit to open the form and select the component (`designer.propertySearch`).

From code to the designer:

- **Show in designer** (#511, Shift+F12, editor context menu, Atlas menu): with the cursor on a form field (`btnOk`), a field use (`btnOk.Caption`, `Self.btnOk`, `frmMain.btnOk`) or in or on a handler assigned in the form, Atlas switches to the “Design” tab, activates the pages of the page controls on the way and selects the component; the Object Inspector shows it. A handler shared by several components (button and menu item) offers them in a menu at the cursor; events of the form (`FormShow`) select the form. Shift+F12 is “View forms” in the IDE; without `keys.editorPriority` the IDE keeps the key and the command stays in the context menu. Switch off with `designer.showInDesigner`, key `designer.showInDesigner.key`.
